# Как устроен SVG-компоновщик

## Карта проекта

| Файл | Зона ответственности |
| --- | --- |
| `src/app/page.tsx` | Маршрут `/`, который открывает редактор. |
| `src/app/layout.tsx` | HTML-оболочка, русский язык и метаданные страницы. |
| `src/app/globals.css` | Внешний вид, состояния элементов и адаптивная сетка. |
| `types/types.ts` | Каталог, размер каждого исходника, пути к SVG и три палитры. |
| `src/components/composer.tsx` | Состояние сцены, форма, выбор палитры, загрузка SVG и команды редактора. |
| `src/components/canvas.tsx` | Векторный предпросмотр, выделение, перетаскивание и сдвиг стрелками. |
| `src/components/inspector.tsx` | Список слоёв, действия над ними и поля свойств. |
| `src/components/icon.tsx` | Иконки кнопок и панелей. |
| `src/lib/matching.ts` | Нормализация запроса и подбор идентификаторов каталога. |
| `src/lib/scene.ts` | Тип слоя, базовый размер холста, размеры и трансформации слоёв. |
| `src/lib/placement.ts` | Роли, опорные точки, оценка перекрытий и размещение объектов. |
| `src/lib/svg.ts` | Загрузка исходников, перекраска, общие SVG-фрагменты и скачивание. |

`public/assets` содержит исходные SVG. В `public/examples` лежат готовые композиции, по которым выбраны пропорции кадра и варианты размещения.

## Как React обновляет сцену

`Composer` хранит список `layers` в `useState`. Состояние `selectedId` содержит идентификатор выбранного слоя. `selected` вычисляется через `layers.find(...)` при рендере, поэтому панель свойств всегда получает актуальный слой.

Сдвиг на холсте и изменение свойства используют одну функцию из `composer.tsx`.

```tsx
function updateLayer(id: string, patch: Partial<Layer>) {
  setLayers((current) => current.map((layer) => layer.id === id ? { ...layer, ...patch } : layer));
}
```

React передаёт в `current` последний список. `map` возвращает новый массив, а `{ ...layer, ...patch }` создаёт копию нужного слоя с обновлёнными полями. React использует `key={layer.id}`, чтобы связать слой с его SVG-группой при смене порядка. В SVG последняя группа рисуется сверху. Панель показывает этот порядок сверху вниз, поэтому разворачивает копию массива через `[...layers].reverse()`.

`useEffect` в `Composer` загружает набор исходников при смене S/L. Флаг `current` в очистке эффекта позволяет игнорировать результат предыдущей загрузки. `useMemo` вычисляет перекрашенные исходники при изменении набора или палитры. `useRef` в `Canvas` хранит параметры активного перетаскивания между рендерами.

## Подбор объектов

В `matching.ts` токенизация приводит запрос к нижнему регистру, заменяет `ё` на `е` и извлекает слова и цифры.

```ts
const tokenize = (text: string) => text.toLowerCase().replaceAll("ё", "е").match(/[\p{L}\p{N}]+/gu) ?? [];
```

В режиме списка `scanNames` начинает с самого длинного возможного сочетания слов. Так `настольная лампа` распознаётся как один объект. Он возвращает идентификаторы по порядку и отдельно собирает неизвестные слова. `и` и `and` служат связками.

В режиме подбора по смыслу точное название приносит 9 баллов. Тематическое совпадение даёт 3 балла, а совпадение с тегом каталога — 2. Узнаваемая метафора добавляет отдельные баллы. Сортировка использует балл и исходный индекс в каталоге, поэтому одинаковый ввод даёт одинаковый результат.

```ts
{ words: "финансовая подушка", assets: ["wallet", "coin"] },
```

У этой фразы кошелёк получает более высокий приоритет. Объекты с нулевым баллом отбрасываются. При полном отсутствии совпадений `generate` показывает подсказку и сохраняет текущую сцену.

## Как рассчитывается раскладка

В `placement.ts` `newLayers` назначает первому предмету роль `focus`, двум следующим — `support`, остальным — `background`. `arrangeLayers` сначала размещает главный слой, чтобы последующие объекты могли учесть его положение. Для одинаковых ролей приоритет получает слой, который рисуется выше. После расчёта координат функция возвращает слои в том же порядке, в котором их получила. В новой сцене `newLayers` разворачивает массив перед раскладкой, чтобы главный объект рисовался поверх остальных.

В пределах холста `x` растёт вправо, `y` вниз. Координаты слоя указывают на его центр. `size` — длина большей стороны в единицах `viewBox`.

```ts
const scale = layer.size / Math.max(source.width, source.height);
return { width: source.width * scale, height: source.height * scale };
```

У книги S размеры 723 × 489. При `size: 300` ширина равна 300, высота — примерно 203. Обе стороны умножаются на один коэффициент. На холсте вложенный SVG начинается в `(-width / 2, -height / 2)`. Поэтому `translate(x y) rotate(angle)` переносит центр в нужную точку и поворачивает объект вокруг неё.

Каждая раскладка задаёт свои координаты, размеры и углы. Алгоритм перебирает смещения и четыре коэффициента масштаба вокруг каждой опорной точки. Стоимость варианта растёт при сильном смещении от опорной точки, уменьшении размера, кадрировании и перекрытии других объектов. `bounds` вычисляет габариты прямоугольника после поворота через синус и косинус угла. `intersection` вычисляет площадь пересечения прямоугольников. Для главных и дополнительных слоёв кандидаты остаются внутри области с отступом 24. Фоновому слою разрешено до 8% кадрирования по площади его габаритов.

В раскладке под заголовок `TITLE_RECT.left` равен 450, поэтому объекты концентрируются в правой части. При числе слоёв больше шести `gridAnchor` рассчитывает опорные точки в сетке.

При перетаскивании координаты браузера нужно перевести в единицы `viewBox`. В `canvas.tsx` это делает обратная матрица холста.

```tsx
return new DOMPoint(event.clientX, event.clientY).matrixTransform(matrix.inverse());
```

При нажатии редактор запоминает разницу между указателем и центром предмета, чтобы предмет двигался от места захвата. Захват указателя поддерживает движение за пределами исходного контура во время перетаскивания.

## Как меняются цвета и собирается файл

`readSvg` загружает локальный файл, разбирает его как XML и читает `viewBox` и внутреннюю разметку. `colorArt` берёт элементы из базовых исходников при каждой смене палитры. `paletteColor` ищет цвет в `PALETTES.lavender` и берёт значение с тем же индексом в целевой палитре.

```ts
const index = PALETTES.lavender.findIndex((original) => original === color.toUpperCase());
return index < 0 ? color : PALETTES[palette][index];
```

Например, заливка `#F9A3AA` занимает индекс 3 и в палитре «Мята» становится `#6D7BFC`. Замена применяется к атрибутам `fill`, `stroke` и `stop-color`. `fill="none"` и значения вне базовой палитры сохраняются. Для задника берётся отдельный исходник нужной палитры. Его квадратный `viewBox` растягивается на весь кадр. У объектов пропорции сохраняются.

Холст и `exportSvg` вызывают одни и те же `backgroundFragment` и `layerFragment`. Фрагменты содержат вложенные `<svg>` с исходными векторными узлами. `scopedBody` добавляет префикс к локальным ID и ссылкам, например `clip-path="url(#…)"`, чтобы одинаковые ID разных фрагментов не конфликтовали. Экспорт оборачивает слои в группы `<g transform="…">` и добавляет корневой `<svg xmlns="…">`. `downloadSvg` превращает строку в `Blob` типа `image/svg+xml` и запускает скачивание через временный URL. Рамка выделения рисуется только компонентом `Canvas`.

## Что даёт TypeScript

- `as const` в каталоге сохраняет строковые литералы. Тип `AssetId = (typeof ASSET_LIBRARY)[number]["id"]` автоматически получает допустимые ID из каталога. Опечатка вроде `"walet"` даёт ошибку компиляции.
- `Record<AssetId, readonly string[]>` для словарей требует запись для каждого объекта. При добавлении нового предмета TypeScript укажет, какие словари нужно дополнить.
- `type PaletteId = "lavender" | "peach" | "mint"` задаёт конечное множество палитр. `satisfies Record<PaletteId, readonly string[]>` проверяет полноту карты и сохраняет конкретные значения `PALETTES`.
- `Partial<Layer>` позволяет передать только изменённые поля. `Partial<Pick<Layer, "x" | "y" | "size" | "angle" | "variant">>` сужает набор полей, доступных панели свойств.
- `ReturnType<typeof colorArt>` связывает тип данных `Canvas` с возвращаемым типом `colorArt`. При смене структуры данных компилятор проверит места её использования.

## Как расширить проект

1. Для нового имени существующего предмета добавьте вариант в `ALIASES`. Для тематических ассоциаций используйте `CONCEPTS`. Например, `подкаст*` уже покрывает «подкасты» и «подкастов». Используйте `PHRASES` для устойчивых выражений, которым нужен определённый порядок предметов.
2. Для изменения композиции сначала измените `x`, `y`, `size` или `angle` в одной из групп `ANCHORS`. Для нового варианта дополните `LAYOUTS`, `LayoutIndex` и `ANCHORS`, затем задайте его область и правила сетки при необходимости.
3. Для уменьшения перекрытий снизьте `allowed` или увеличьте штраф после порога в `place`. Проверьте запрос с одним предметом, несколько разных пропорций и плотный список. Отдельно проверьте, что в варианте под заголовок осталось место слева.
4. При добавлении разрешённого исходника обновите каталог, словари и оба SVG-варианта для S и L. Сверьте размеры каталога с `viewBox`. Проверьте, какие атрибуты несут цвета. Текущая замена рассчитана на атрибуты в библиотеке и потребует расширения для цветов в CSS.
5. Сравните один и тот же запрос во всех палитрах и размерах. После ручного поворота и перестановки слоёв скачайте SVG. Проверьте в XML наличие `<path>`, векторных трансформаций и палитры, затем откройте файл отдельно и сравните с холстом.
